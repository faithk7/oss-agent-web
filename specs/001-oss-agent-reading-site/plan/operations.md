# 运维、部署与恢复计划

## 托管与媒体

Vercel/无状态多实例不能依赖进程本地 `media/` 持久化。v1 必须二选一：使用带持久卷的 VPS，或把私有媒体放入支持私有对象和鉴权读取的存储；切换时保留 `article_media` 元数据和 hash 地址契约。禁止将付费媒体放入 `public/`。

## 发布流程

先备份，再执行向前兼容迁移；迁移成功后部署应用；最后运行内容同步和 smoke tests。生产发布前必须通过各通道可用测试环境与启用前真实联调、付费正文泄漏扫描和回滚演练。支付入口由 feature flag 控制，旧版本可安全拒绝新 checkout。

## 备份与恢复

Postgres 加密备份、每日全量+连续 WAL（按托管能力），定期恢复到隔离环境并记录 RPO/RTO。密钥可轮换，备份和日志不得包含兑换码明文、支付密钥或正文。

## 任务与清理

CLI 使用 advisory lock；数据库 job 记录含 lease/过期时间，崩溃后可接管。cron 重入返回可识别的跳过状态。定期执行 pending 订单对账、webhook 失败重试、媒体 orphan GC、限流桶清理和审计保留策略。

## 可观测性

提供健康检查（进程/数据库）和 readiness（迁移版本/关键配置）。结构化日志脱敏；指标包括同步失败、webhook 延迟/失败、pending 订单、兑换冲突、429、正文拒绝和数据库连接池。关键告警有明确操作手册。

## 通道上线与故障隔离

| 能力 | 准入与配置 | 启用门禁 |
|---|---|---|
| 微信网站登录 | 开放平台网站应用、批准的回调域、AppID/Secret | 扫码成功、取消、过期、重放、账号绑定 |
| 微信支付 | 商户、支付 AppID 绑定、Native/H5/JSAPI 各自产品权限、API v3 密钥与验签材料 | 实际已开通场景的支付、查单、通知及退款 |
| 支付宝 | 商户应用、电脑/手机网站支付产品、签名模式及异步通知地址 | 可用 sandbox 加启用前真实支付/退款 |
| Stripe | 独立商户准入、产品和签名凭据 | sandbox 和生产配置检查 |

阶段 1 即启动审核清单；凭据缺失不阻止本地 mock/合约实现，但不等于完成上线验证。微信支付不假设存在与生产等价的通用 sandbox；记录当时产品实际测试能力及受控小额实付/退款证据。

通道开关独立；关闭新下单时保留旧订单通知、查单和退款处理。监控按 provider 分组记录下单错误、签名错误、待支付积压、通知延迟和对账差异。状态查询本地限频，后台查单按供应商配额退避。证书/公钥轮换同时覆盖在途订单。

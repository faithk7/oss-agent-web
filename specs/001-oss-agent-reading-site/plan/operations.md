# 运维、部署与恢复计划

## 托管与媒体

生产环境为一家中国大陆云（阿里云／腾讯云择一）：MVP 应用是单个 ECS 或容器上的 Node 进程，数据库用托管 PostgreSQL 16（自带加密备份与 WAL）。本地 POC 可用私有持久卷；生产媒体使用 `MediaStore` 的私有 OSS/COS 实现，避免滚动发布或重启丢失文件。禁止将付费媒体放入 `public/`。CDN 分层：静态产物与 `public_since` 非空的公开媒体经厂商 CDN 分发（加速域名需 ICP 备案，备案完成后启用）；付费媒体保持鉴权代理，不进公共缓存。

## 发布流程

先备份，再执行向前兼容迁移；迁移成功后部署应用；最后运行内容同步和 smoke tests。生产发布前必须通过已启用通道的测试环境与真实联调、付费正文泄漏扫描（含经 CDN 域名请求付费路径确认 `no-store` 透传、无共享缓存命中）、回滚演练，并确认 ICP 备案完成、支付回调域名与 CDN 加速域名已备案启用。微信 Native 与支付宝电脑网站支付是 MVP 启用门禁；移动场景、Stripe 和额外登录 provider 各自使用独立 feature flag，旧版本可安全拒绝新 checkout。

## 备份与恢复

Postgres 加密备份、每日全量+连续 WAL（按托管能力），定期恢复到隔离环境并记录 RPO/RTO。密钥可轮换，备份和日志不得包含兑换码明文、支付密钥或正文。

## 任务与清理

定时任务以境内主机 cron 为准（跨境 CI 调库不作为生产路径）。CLI 只使用 `pg_try_advisory_lock`；连接断开时锁自动释放，cron 重入返回可识别的跳过状态。定期执行 pending 订单对账、失败 webhook 重试、媒体 orphan GC、限流桶清理和审计保留策略。媒体 GC 不删除 `public_since` 非空对象。

## 可观测性

提供健康检查（进程/数据库）和 readiness（迁移版本/关键配置）。结构化日志脱敏；指标包括同步失败、webhook 延迟/失败、pending 订单、兑换冲突、429、正文拒绝和数据库连接池。关键告警有明确操作手册。

## 通道上线与故障隔离

| 能力 | 准入与配置 | 启用门禁 |
|---|---|---|
| 微信网站登录 | 开放平台网站应用、批准的回调域、AppID/Secret | MVP 扫码成功、取消、过期、重放 |
| 微信支付 | 商户、支付 AppID 绑定、Native 产品权限、API v3 密钥与验签材料 | MVP 桌面二维码支付、查单、通知 |
| 支付宝 | 商户应用、电脑网站支付产品、签名模式及异步通知地址 | MVP sandbox 加启用前真实支付 |
| 移动支付扩展 | H5／JSAPI／手机网站产品权限 | 每个场景独立真实设备验证 |
| Stripe 扩展 | 独立商户准入、产品和签名凭据 | sandbox 和生产配置检查 |

可行性阶段即启动审核清单（含 ICP 备案办理：站点、支付／回调域名、CDN 加速域名）；凭据缺失不阻止本地 fixture／合约实现，但不等于完成上线验证。微信支付不假设存在与生产等价的通用 sandbox；记录当时产品实际测试能力及受控小额实付证据。

通道开关独立；关闭新下单时保留旧订单通知与查单。监控按 provider 分组记录下单错误、签名错误、待支付积压、通知延迟和对账差异。状态查询本地限频，后台查单按供应商配额退避。证书/公钥轮换同时覆盖在途订单。

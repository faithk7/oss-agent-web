# 验收标准与测试矩阵

## 权限矩阵

| 资源 | 匿名 | 登录无权益 | 登录有权益 | 管理员 |
|---|---|---|---|---|
| 免费文章 | 正文 | 正文 | 正文 | 正文 |
| 付费文章 | 试读 | 试读 | 正文 | 正文 |
| 草稿/归档 | 404 | 404 | 404 | 404（无管理预览） |
| 付费媒体 | 404 | 404 | 200 | 200 |
| 搜索/推荐 | 已发布元数据 | 已发布元数据 | 已发布元数据 | 已发布元数据 |

## 必须通过的检查

- 2k 篇文章搜索 `p95 < 300ms`，并有 `EXPLAIN` 基准和索引。
- 200 个 Markdown 文件无模型调用同步 `< 30s`；失败、dry-run、不完整扫描和重命名测试通过。
- 付费正文不出现在 build 输出、HTML、RSC、错误页、公共缓存、日志或未授权媒体响应。
- 同一 webhook、兑换码和并发购买均只产生一次有效授予；管理员撤销只影响对应来源。
- 旧 slug 命中 `article_redirects` 返回 301；已发布 slug 变更缺重定向条目时同步报错且不发布。
- `preview=custom` 缺 `preview_markdown` 时同步报错；30% 试读在小节／段落边界收尾、同步时生成；经 CDN 域名请求付费路径确认无缓存命中。
- 词表外新词提议未接受前 `public=false`，不出现在公开筛选，也不进入搜索标签。
- 支付通知路由不受 IP 限流影响，服务商重试可正常送达。
- 上线前 ICP 备案完成；支付回调域名与 CDN 加速域名均已备案并启用。
- 付费/免费、中文/英文、日期时区、重定向、标签 AND、媒体 visibility 转换均有集成测试。
- sanitizer、SVG/Mermaid 资源限制、CSRF、代理 IP、管理员 CLI 审计和 PaymentProvider contract tests 通过。
- 各支付通道的通知与查单、乱序/重放/金额不符事件、pending 对账和恢复演练通过。

## 阶段完成定义

每个阶段必须有迁移、自动化测试、失败回滚说明、运行手册更新和可复现的 smoke test。阶段 1 即使尚未实现权益模块，也必须有 deny-by-default 集成门禁，确保已入库的 `body_html` 无任何页面、RSC、序列化器或静态资源路径可返回。

## 新增 v1 必验：微信登录、微信支付、支付宝

- 微信桌面扫码登录成功、拒绝、过期、state 不匹配、code 重放、首次无邮箱用户、退出后重新登录、绑定已有 GitHub/邮件账号和绑定冲突。
- 微信 Native 桌面二维码与支付宝电脑网站支付完成完整链路；H5/JSAPI/支付宝手机网站支付按已声明支持场景逐项真实设备验证，不将所有浏览器等同处理。
- 所有登录方式均可选择任一已开通支付通道；JSAPI 不复用网站 openid，付款人不同于登录用户时权益仍归属服务器订单用户。
- 三通道分别覆盖正确支付、错误商户/AppID、金额/币种不符、重复/乱序通知、通知丢失后查单、创建超时重试、关闭/过期订单迟到付款、二维码刷新、取消回跳、签名材料轮换。
- 不同通道交易 id 相同不会碰撞；同一真实订单不同事件仅授予一次；同用户两笔真实付款正确叠加。
- 各通道回执符合自身协议（特别是支付宝纯文本 success）；订单轮询不可越权；禁用新支付后仍接收旧订单回调。
- 阶段 3 完成必须包含微信登录测试；阶段 4 的微信支付和支付宝不得由 Stripe 或兑换码替代验收。mock/fixture 通过不等于商户审核或实付联调完成。

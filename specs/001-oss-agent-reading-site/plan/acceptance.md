## MVP 成功标准的验证方式

下列是产品层的成功门槛；每项都要有可复现证据，不能以 mock 成功页、未验签回跳或未开通的支付产品替代。扩展 provider 不计入 MVP 通过／失败。

| 成功标准 | 验证证据 |
| --- | --- |
| 内容可发布、可发现 | 干净数据库同步免费／付费及中／英文 fixture；文章库、标题搜索、标签 AND、推荐和错误文件回滚 smoke test 通过。 |
| 付费边界成立 | 匿名／无权益／有权益／到期／撤销访问矩阵通过；正文泄漏扫描覆盖 HTML、RSC、静态包、公共缓存和未授权媒体。 |
| 身份与兑换闭环成立 | 桌面微信登录成功／取消／过期／state 与 code 重放测试通过；真实 Postgres 下同码并发只有一个授予，重复兑换不延长。 |
| 国内桌面支付闭环成立 | 微信 Native 与支付宝电脑网站各完成可用测试或受控小额实付；验签通知、查单、重试、乱序和金额核对最终只产生一次授予。 |
| 轻量部署可运营 | 单 Web 进程 + PostgreSQL + CLI 的启动、readiness、备份恢复和 smoke test 可复现；2k 篇文章搜索 warm p95 < 300ms、200 个 Markdown 无模型同步 < 30s。 |

## 必须通过的检查

- 2k 篇文章搜索 `p95 < 300ms`，在固定 warm 单实例、同地域 Postgres、10 个并发和 500 次请求的基准中测量，并有 `EXPLAIN` 与索引记录。
- 200 个 Markdown 文件无模型调用同步 `< 30s`；失败、dry-run、不完整扫描、不可变 id 重命名和符号链接测试通过。
- 付费正文不出现在 build 输出、HTML、RSC、错误页、公共缓存、日志或未授权媒体响应。
- 同一 webhook、兑换码和并发购买均只产生一次有效授予；管理员撤销只影响对应来源；撤销后的后续请求不能读正文。
- 旧 slug 命中 `article_redirects` 返回 301；已发布 slug 变更缺重定向条目时同步报错且不发布；重命名后旧重定向仍指向当前 slug。
- `preview=custom` 缺 `preview_markdown`、超过 `PREVIEW_MAX_WEIGHTED_CHARS` 或等同完整正文时同步报错；30% 试读在小节／段落边界收尾、同步时生成；经 CDN 域名请求付费路径确认无缓存命中。
- 同一媒体 hash 被两篇文章引用时不产生冲突；曾公开的 hash 永不切回私有；付费媒体必须使用 article-scoped URL，跨文章访问返回 404。
- 词表外新词提议未接受前 `public=false`，不出现在公开筛选，也不进入搜索标签。
- tagger 失败或过期时旧标签保留；同一内容只按 article、hash、tagger version 和 input scope 跳过；人工拒绝不被自动重跑覆盖。
- 支付通知路由不受 IP 限流影响，服务商重试可正常送达。
- 上线前 ICP 备案完成；支付回调域名与 CDN 加速域名均已备案并启用。
- 付费/免费、中文/英文、日期时区、重定向、标签 AND、媒体 public_since 永久公开规则均有集成测试。
- sanitizer、SVG/Mermaid 资源限制、CSRF、代理 IP、管理员 CLI 审计和 PaymentProvider contract tests 通过。
- MVP 的微信 Native 与支付宝电脑网站通知／查单、乱序／重放／金额不符事件、pending 对账和恢复演练通过；移动场景与 Stripe 启用前逐项复用相同 contract tests 和门禁。
- 同一支付事件失败后以相同 payload 重试可以成功处理；相同 event id 的不同 payload hash 会拒绝并告警；已支付订单收到迟到失败事件不会回退。

## 阶段完成定义

可行性阶段必须产出 provider／场景能力矩阵、域名／备案清单、MediaStore 选择和可复现的登录／支付 fixture；没有真实商户能力时不得标记支付上线。其后每个阶段必须有迁移、自动化测试、失败回滚说明、运行手册更新和可复现的 smoke test。阶段 1 即使尚未实现权益模块，也必须有 deny-by-default 集成门禁，确保已入库的 `article_bodies.body_html` 无任何页面、RSC、序列化器或静态资源路径可返回。

## MVP 必验：微信登录、微信 Native、支付宝电脑网站支付

- 微信桌面扫码登录成功、拒绝、过期、state 不匹配、code 重放、首次无邮箱用户和退出后重新登录。
- 微信 Native 桌面二维码与支付宝电脑网站支付完成完整链路；移动 H5/JSAPI/支付宝手机网站和 Stripe 启用前逐项真实验证，不将所有浏览器等同处理。
- MVP 登录用户可选择任一已启用的国内桌面支付通道；未来 JSAPI 不复用网站 openid，付款人不同于登录用户时权益仍归属服务器订单用户。
- 两个 MVP 通道覆盖正确支付、错误商户/AppID、金额／币种不符、重复／乱序通知、通知丢失后查单、创建超时重试、关闭／过期订单迟到付款、二维码刷新、取消回跳和签名材料轮换。
- 不同通道交易 id 相同不会碰撞；同一真实订单不同事件仅授予一次；同用户两笔真实付款正确叠加。
- 各通道回执符合自身协议（特别是支付宝纯文本 success）；订单轮询不可越权；禁用新支付后仍接收旧订单回调。
- 阶段 3 完成必须包含微信登录测试；阶段 4 的微信支付和支付宝不得由 Stripe 或兑换码替代验收。fixture 通过不等于商户审核或实付联调完成。
